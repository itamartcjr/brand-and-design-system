# MASTER PROMPT — gerar o Brand Framework completo

```text
Use o repositório https://github.com/itamartcjr/brand-and-design-system e o Figma https://www.figma.com/design/99947Dmc328mSa2FmYj5fP/Brand-e-Design-System?node-id=0-1&t=XyywlRgk12fIPGlo-1 como referência estrutural obrigatória para construir o Brand Framework deste projeto.

ESTRUTURA: deve permanecer equivalente à referência. Preserve posição da marca/logo, sidebar, busca, organização grupo → módulo → item, accordions, item ativo, topbar, breadcrumb, link/funções da topbar, alternância de tema, workspace, comportamento mobile e lógica de rotas. Não redesenhe essa arquitetura.

IDENTIDADE: deve ser a do projeto atual. Troque marca, fontes, cores, fotografia, ilustração, ícones, superfícies, motion e microinterações conforme a identidade real da marca. Copie a inteligência estrutural; não copie a estética.

CONTEÚDO: leia `docs/brand/PAGE-SPEC.md` e depois execute todos os masters de grupo, nesta ordem: 01-foundation, 02-language-narrative, 03-visual-identity, 04-experience, 05-ai-governance. Dentro de cada grupo, abra todos os módulos na ordem numérica. Dentro de cada módulo, leia a fonte de verdade e execute TODOS os `fields` na ordem, sem pular nenhum.

Cada `field` deve resultar em uma página completa, não em uma linha de checklist. Use título, definição, propósito, perguntas, evidência, decisão da marca, exemplo real, contraexemplo quando aplicável, como executar, modelo, visualização, dependências e referências.

Não invente estratégia ou pesquisa. Classifique o conteúdo como: confirmado, aprovado, evidenciado, hipótese ou pendente. Quando um item depender de pesquisa ainda inexistente, construa a página com método, perguntas, estrutura e estado pendente em vez de fabricar respostas.

PÁGINAS MASTER: masters não substituem seus filhos. Um master deve explicar sequência, dependências, critérios de conclusão e mandar executar todos os filhos. Só marque o master como concluído quando cada filho estiver implementado e revisado.

QUALIDADE VISUAL: o Brand Book não deve parecer um documento de texto automático. Cada decisão deve ganhar a melhor forma visual para ser ensinada: mapas, matrizes, escalas, diagrams, before/after, specimen, storyboards, timelines, galleries, do/don't, exemplos reais e aplicações.

Ao final, faça revisão cruzada: Core deve sustentar Strategy; Strategy deve sustentar Audience e Personality; linguagem deve refletir Personality; identidade visual deve refletir Strategy; Experience deve demonstrar consistência entre canais; AI Guidelines deve traduzir decisões existentes, não criar uma marca paralela; Governance deve registrar owners, versões, aprovações e mudanças.
```

## Regra de conclusão

O framework só está completo quando os 20 módulos e todos os seus itens internos estiverem executados ou explicitamente marcados como pendentes com método de obtenção da informação.
